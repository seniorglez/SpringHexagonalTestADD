# 04 · Design

This file prescribes structure so that the implementation is predictable and reviewable. Names
are part of the spec. The frozen architecture tests depend on the package layout.

## Package layout (base package `com.seniorglez.prices`)

```
com.seniorglez.prices
├── PricesApplication                         generated by Spring Initializr, frozen
├── domain
│   ├── model/Price                           record with invariants and isApplicableAt
│   ├── service/PriceSelector                 selection policy (priority, then tie-break)
│   └── exception/PriceNotFoundException      unchecked; carries brandId, productId, applicationDate
├── application
│   ├── port
│   │   ├── in/FindApplicablePriceUseCase     interface: Price find(FindApplicablePriceQuery query)
│   │   ├── in/FindApplicablePriceQuery       record(long brandId, long productId, LocalDateTime applicationDate)
│   │   └── out/LoadPricesPort                interface: List<Price> loadCandidates(long brandId, long productId, LocalDateTime at)
│   └── service/FindApplicablePriceService    implements FindApplicablePriceUseCase
└── infrastructure
    ├── config/ApplicationConfig              @Configuration: declares PriceSelector and FindApplicablePriceService beans
    └── adapter
        ├── in/rest
        │   ├── PriceController               GET /prices
        │   ├── PriceResponse                 record, JSON body of 200
        │   └── RestExceptionHandler          @RestControllerAdvice → problem details
        └── out/persistence
            ├── PriceJpaEntity                maps table PRICES
            ├── SpringDataPriceRepository     Spring Data JPA repository
            ├── PriceEntityMapper             entity → domain
            └── PricePersistenceAdapter       implements LoadPricesPort
```

Adding a small private helper class inside a package is fine. Adding new packages or layers is not.

## Flow of a request

1. `PriceController` binds and validates the parameters (`@Positive` on ids, ISO date-time
   format), builds a `FindApplicablePriceQuery` and calls `FindApplicablePriceUseCase`.
2. `FindApplicablePriceService` calls `LoadPricesPort.loadCandidates(...)`, then passes the
   result to `PriceSelector.select(...)`. If the result is empty, it throws
   `PriceNotFoundException`.
3. `PricePersistenceAdapter` queries `SpringDataPriceRepository` for rows matching brand, product
   and `start_date <= at <= end_date`, and maps them with `PriceEntityMapper`.
4. `PriceController` maps the domain `Price` to `PriceResponse`.

`FindApplicablePriceQuery` validates its own invariants (ids > 0, date not null) and throws
`IllegalArgumentException`. The web layer rejects invalid input first, so in practice those
checks only catch programming errors.

## Wiring

- Application and domain classes carry **no** annotations. `ApplicationConfig` creates them with
  `@Bean` methods, using constructor arguments.
- Infrastructure classes use the normal stereotypes (`@RestController`, `@Component`/`@Repository`,
  `@RestControllerAdvice`) and are found by the default component scan from `PricesApplication`.
- Constructor injection everywhere.

## Persistence

- The schema is **given**: `schema.sql` and `data.sql` (frozen). Hibernate never creates the schema.
- Table `PRICES`: `id BIGINT` (PK, identity), `brand_id BIGINT`, `start_date TIMESTAMP`,
  `end_date TIMESTAMP`, `price_list INTEGER`, `product_id BIGINT`, `priority INTEGER`,
  `price DECIMAL(10,2)`, `curr VARCHAR(3)`.
- `PriceJpaEntity` maps those columns. The JPA field for `price` is called `amount` and the one
  for `curr` is called `currency`, so the entity reads naturally while the table keeps the names
  of the original statement.
- Repository query: prefer a named-parameter JPQL `@Query` for readability. A derived query is
  acceptable.
- The adapter returns all candidates. It **does not** pick the winner (that is the domain's job).

## Web

- `@DateTimeFormat(iso = DateTimeFormat.ISO.DATE_TIME)` on `applicationDate`.
- `@Positive` on `productId` and `brandId`, which are declared as `long`/`Long` request parameters.
- `PriceResponse` is a record whose component names are exactly the JSON field names of the contract.
- Dates are serialised as ISO strings (the Spring Boot default). Do not add Jackson modules.

## Error handling (`RestExceptionHandler`)

`RestExceptionHandler` extends `ResponseEntityExceptionHandler`, so Spring's standard web
exceptions (missing parameter, type mismatch, method validation, method not allowed) already become
`ProblemDetail`s with the correct status and headers. It also adds:

| Exception | Status | Notes |
|---|---|---|
| `PriceNotFoundException` | 404 | `detail` built from brand, product and date |
| any other `Exception` | 500 | `detail` = `An unexpected error occurred.`; log the exception at ERROR with its stack trace |

Check the inherited mappings against the contract. Every 400 case in the contract must produce 400,
not 500.

## Configuration (`src/main/resources/application.properties`)

Required settings. You may add others only if a test needs them.

```properties
spring.application.name=prices
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.open-in-view=false
spring.sql.init.mode=always
```

Do not set `spring.datasource.url`. Spring Boot's embedded H2 with a unique name per Spring context is
intended, so every test context gets a fresh database seeded by the frozen scripts.

`ddl-auto=validate` is deliberate. It proves that the entity mapping matches the given schema. If
validation fails, fix the **entity mapping**, never the schema.

## Test strategy per layer

| Layer | Test class(es) | Style |
|---|---|---|
| domain | `PriceTest`, `PriceSelectorTest` | plain JUnit, no Spring |
| application | `FindApplicablePriceQueryTest`, `FindApplicablePriceServiceTest` | plain JUnit, hand-written in-memory fake of `LoadPricesPort` |
| persistence adapter | `PricePersistenceAdapterTest` | Spring test against the real H2 seed |
| REST adapter | `PriceControllerTest` | Spring MVC test with a fake or mocked `FindApplicablePriceUseCase` |
| acceptance (frozen) | `PriceApiAcceptanceTest` | black-box HTTP |
| architecture (frozen) | `HexagonalArchitectureTest` | ArchUnit |

Unit tests mirror the production packages under `src/test/java`. Use the Spring Boot test-slice
annotations that are available with the frozen dependencies. If a slice is not available, use
`@SpringBootTest` instead. Never add dependencies.
